# 题目4功能缺失核对清单

依据：`设计要点_题目4_学生公寓宿舍管理系统.docx`。本清单记录补充前的缺失项、完成标准和实际验证结果。

## 缺失项完成核对

- [x] 学生自助注册：注册时填写账号、密码及学生资料；只创建学生角色，账号与学生档案在同一事务内建立。
- [x] 报修位置：提交时选择宿舍并保存，历史报修位置不随退宿或房间改名变化。
- [x] 报修完成说明：管理员填写说明后才能将处理中报修标记完成，详情可查看说明。
- [x] 报修满意度：学生选择满意或不满意并填写评语；终态统一显示“已评价”，禁止重复评价。
- [x] 访客登记：管理员维护访客姓名、被访学生、来访及离开时间，支持增删改查和分页。
- [x] 学生建议字段：增加班级、联系电话，支持管理员维护与学生查看和维护。
- [x] 宿舍建议字段：增加房间类型，支持管理员维护与列表展示。
- [x] 概览按角色展示：学生查看个人住宿与报修概览；管理员查看全局统计和各宿舍床位；未登录仅查看整体入住率及报修处理率。
- [x] 统计口径：入住率为占用床位数除以总床位数；报修处理率为已完成及已评价数除以全部报修数，评价后不降低处理率。
- [x] 数据初始化：统一由 `sql/init.sql` 提供当前完整表结构、约束与示例数据，仅保留一份初始化 SQL。
- [x] 验证：完成后端构建、前端构建及覆盖新增业务与权限的测试，记录实际结果。

## 保留的已有实现

- 学生与床位通过入住记录关联；退宿解除有效关联，保留历史床位记录。
- 入住申请选择具体床位，选项包含楼栋、房间及床位；管理员确认时再次检查空闲状态。
- 分配与退宿使用事务、行锁及数据库唯一约束。
- 保留报修内部状态值 `CONFIRMED`，将其界面含义统一为“已评价”，兼容已有记录。
- 房间床位色块属于加分项，当前彩色状态标签继续保留。

## 数据库初始化

在全新数据库中执行一次 `sql/init.sql`，或由 Docker 在首次建立数据卷时自动执行。初始化脚本包含所有当前功能所需表结构，无需额外迁移脚本；本次整理文件未改动运行中的数据库。

## 实现入口

- `frontend/src/App.vue`：注册、报修位置与说明、满意度表单、公共统计入口。
- `frontend/src/views/Page.vue`：学生资料、报修详情、访客列表及统计展示。
- `src/main/java/cn/edu/dorm/BusinessService.java`：注册事务、报修状态与位置存储、资料及统计。
- `src/main/java/cn/edu/dorm/AdminService.java`：访客 CRUD、时间校验、班级电话及房间类型。
- `sql/init.sql`：完整数据库初始化。
- `scripts/smoke_test.py`、`frontend/tests/topic4.spec.js`：新增功能验收测试。
